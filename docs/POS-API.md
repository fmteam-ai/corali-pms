# Σύνδεση POS με το Corali PMS (v184)

Οδηγός για τον τεχνικό του POS κάθε τμήματος (μπαρ, εστιατόριο, spa, γυμναστήριο, ξαπλώστρες).

## 1. Κλειδί

PMS → Τμήματα → **Πωλήσεις** → «Σύνδεση POS ανά τμήμα» → **Δημιουργία κλειδιού** στο τμήμα.
Το κλειδί (`cpos_…`) εμφανίζεται **μία φορά** και ανήκει σε **ένα** τμήμα: ό,τι στέλνει το POS με αυτό
το κλειδί μετράει σε αυτό το τμήμα. «Νέο κλειδί» ακυρώνει το παλιό· «Αποσύνδεση» το σταματά.

Κάθε αίτημα: `Authorization: Bearer cpos_…`, JSON, στη διεύθυνση του **PMS** (π.χ. `https://pms.hotelcorali.gr`).
Όριο: 240 αιτήματα το λεπτό ανά τμήμα.

**Πάντα η δημόσια διεύθυνση (μέσω Cloudflare)**, ποτέ η IP του server: με ενεργό το «Κλείδωμα πίσω από το Cloudflare»
(Κέντρο ασφαλείας) ο server απαντά 403 σε ό,τι δεν περνά από το Cloudflare. Αν το WAF του Cloudflare μπλοκάρει το POS,
προσθέστε κανόνα «Skip» για τη διαδρομή `/api/v1/pos/`.

## 2. Απόδειξη — `POST /api/v1/pos/sales`

```json
{
  "receipt_id": "Z12-004512",
  "sold_at": "2026-07-15T21:10:00+03:00",
  "payment": "room",
  "room": "112",
  "covers": 2,
  "items": [
    { "name": "Mojito", "sku": "MOJ", "quantity": 2, "unit_price": 9.5 },
    { "name": "Νερό 0,5", "sku": "W05", "quantity": 1, "unit_price": 1 }
  ],
  "total": 20
}
```

- `receipt_id` (υποχρεωτικό): ο αριθμός της απόδειξης. **Η ίδια απόδειξη δεύτερη φορά δεν μετράει ξανά** — ασφαλές να
  ξαναστείλετε μετά από σφάλμα δικτύου (απάντηση `200` με `duplicate: true`· η πρώτη φορά `201`).
- `payment`: `cash`, `card`, `room` (χρέωση στο δωμάτιο), `other`.
- `room`: αριθμός δωματίου πελάτη που μένει τώρα ή κωδικός κράτησης. **Υποχρεωτικό για `room`**: το ποσό μπαίνει αμέσως
  στον λογαριασμό (folio) του πελάτη. Για μετρητά / κάρτα είναι προαιρετικό (μετράει ότι αγόρασε πελάτης του ξενοδοχείου).
- `items`: όνομα, `sku` (ο κωδικός του είδους στο POS — συμπληρώστε τον και στο PMS, «Κωδικός στο POS», ώστε να
  ταιριάζει με τον κατάλογο), ποσότητα, τιμή μονάδας σε €. Χωρίς `items` αρκεί το `total`.
- `total` (€): αν δοθεί μαζί με items πρέπει να συμφωνεί (±0,05 €).
- `sold_at`: ISO ώρα· χωρίς αυτό, η ώρα λήψης.

Σφάλματα: `400` (λάθος στοιχεία, το `message` λέει τι), `401` (κλειδί), `404` (δεν μένει κανείς στο δωμάτιο),
`409` (η κράτηση δεν είναι ανοιχτή), `429` (όριο).

## 3. Ακύρωση — `DELETE /api/v1/pos/sales/{receipt_id}`

Η απόδειξη βγαίνει από τις πωλήσεις· αν ήταν χρέωση δωματίου, αφαιρείται από τον λογαριασμό του πελάτη.

## 4. Πριν τη «χρέωση στο δωμάτιο» — `GET /api/v1/pos/guest?room=112`

```json
{ "ok": true, "data": { "reference": "CR-2607-1234", "room": "112", "guest": "Anna M.", "check_out": "2026-07-18", "can_charge": true } }
```

Μόνο μικρό όνομα και αρχικό επωνύμου, για να επιβεβαιώσει ο σερβιτόρος τον πελάτη.

## 5. Είδη — `GET /api/v1/pos/items`, `PUT /api/v1/pos/items`

`PUT` με `{ "items": [ { "sku": "MOJ", "name": "Mojito", "name_en": "Mojito", "price": 9.5, "active": true } ] }`:
ταιριάζει με τον κωδικό POS, ενημερώνει όνομα / τιμή, προσθέτει τα νέα. Τα ενεργά εμφανίζονται και στην εφαρμογή
των πελατών (παραγγελία με χρέωση στο δωμάτιο).

## 6. Χωρίς σύνδεση: αρχείο CSV

PMS → Τμήματα → Πωλήσεις → «Εισαγωγή πωλήσεων από αρχείο». Μία γραμμή ανά είδος, στήλες (ελληνικά ή αγγλικά):
`Ημερομηνία;Ώρα;Απόδειξη;Είδος;Ποσότητα;Τιμή;Πληρωμή;Δωμάτιο` — π.χ. `15/07/2026;21:10;1001;Mojito;2;9,50;Κάρτα;`.
Οι αποδείξεις που υπάρχουν ήδη δεν διπλασιάζονται. Οι χρεώσεις δωματίου του αρχείου **δεν** ξαναχρεώνονται.

## 7. Έλεγχος

Μετά την πρώτη απόδειξη, στο PMS: «Συνδεδεμένο · Τελευταία πώληση …». Αν το POS σταματήσει να στέλνει για 48 ώρες ενώ
το τμήμα πουλάει, ο Βοηθός πωλήσεων βγάζει προειδοποίηση.
