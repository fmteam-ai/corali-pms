# Corali TV — Hotel Mode: επαναφορές & Emergency Unlock (PMS v160, εφαρμογή 1.10)

Υλοποίηση της προδιαγραφής «TV-HOTEL-MODE-RESET-v160-SPEC». Πιλοτική TV: HORIZON 43HQ8590U/D, δωμάτιο 112.

## 1. Τι υλοποιήθηκε

PMS → Corali TV → **Ήχος & Hotel Mode** → «Επαναφορές (μόνο στα επιλεγμένα δωμάτια)».

| Ενέργεια | Δικαίωμα | Επίδραση | Επιβεβαίωση |
|---|---|---|---|
| **Επαναφορά προεπιλογών ξενοδοχείου** | integrations.write | πολιτική = προεπιλογές ξενοδοχείου (αρχικά 8% / 30% / επιβολή), μετά `UNMUTE` | `UNMUTE` EXECUTED **και** η TV αναφέρει ότι έχει τη νέα πολιτική (`prev` ≥ rev) |
| **Κατάργηση περιορισμού μέγιστης έντασης** | integrations.write | `enforce_max=false`, η ένταση εκκίνησης μένει. Δεν σημαίνει εργοστασιακό μέγιστο 100% | η TV αναφέρει τη νέα πολιτική |
| **Επαναφορά ήχου τώρα** | reservations.write (ρεσεψιόν) ή admin | `UNMUTE` + `SET_VOLUME` στην ένταση εκκίνησης του δωματίου (με το όριο). Η πολιτική δεν αλλάζει | μετρημένη ένταση / σίγαση (όπως στη v159) |
| **Επαναφορά Hotel Mode** | integrations.write | μόνο οι πολιτικές λογισμικού: πολιτική = προεπιλογές, `UNMUTE`, `SET_VOLUME` | ανά δωμάτιο· γραμμή «Εργοστασιακό κλείδωμα μενού: UNSUPPORTED (δεν αγγίχτηκε)» |
| **Emergency Unlock Menu** | — | **δεν υποστηρίζεται**: απενεργοποιημένο κουμπί και οδηγία για τεχνικό (Factory Menu → Engineer Mode Option → Lock Menu Key → Off). Δεν στέλνεται ποτέ, και δεν εμφανίζεται ποτέ «ξεκλειδώθηκε» | — |

Οι **προεπιλογές ξενοδοχείου** ρυθμίζονται από τον διαχειριστή στην ίδια ενότητα («Αποθήκευση προεπιλογών»). Αποθηκεύονται στις ρυθμίσεις ρεύματος TV του καταλύματος (`soundPreset`) και δεν είναι hardcoded.

**Δεν** υπάρχει factory reset της TV. **Δεν** αγγίζονται: `tv_screens.token`, Wi-Fi, μέθοδος ρεύματος, Shelly, καλωσόρισμα, κρατήσεις, ρυθμίσεις Realtek / Expressluck. Επαληθεύτηκε στη δοκιμή (token και power_method αμετάβλητα).

## 2. Ασφάλεια / UX

- Μόνο τα **επιλεγμένα** δωμάτια, ποτέ σιωπηρά «όλα».
- Διάλογος με: τι αλλάζει (με τις τιμές), τα δωμάτια, και «Δεν πραγματοποιείται εργοστασιακή επαναφορά». Για >1 δωμάτια, επιπλέον πληκτρολόγηση του πλήθους.
- `idempotencyKey` (UUID ανά πάτημα): η επανάληψη επιστρέφει το αρχικό αίτημα, χωρίς δεύτερη εφαρμογή (`tv_reset_requests` UNIQUE(owner, key)).
- Audit: `tv_reset_requests` (ενέργεια, δωμάτια, χρήστης, ώρα, πολιτικές πριν/μετά, εντολές) και το γενικό ιστορικό ενεργειών (`tv_sound`).
- Έλεγχος origin, session, δικαιώματα ανά ενέργεια, όριο 20 επαναφορών / 15′ ανά χρήστη, φιλτράρισμα ανά owner.
- `roomIds` = εσωτερικό `rooms.id` / `tv_screens.room_id`. Ο server ελέγχει ότι ανήκουν στο κατάλυμα. Το PMS εμφανίζει τον αριθμό δωματίου.
- Επιθυμητή κατάσταση (`tv_sound_policies`) χωριστά από αναφερόμενη (`tv_screens.volume_*`, `policy_rev_applied`).

## 3. Κατάσταση ανά δωμάτιο

`PENDING` · `DELIVERED` · `EXECUTED` (μόνο με αναφορά της TV) · `UNVERIFIED` · `FAILED` · `OFFLINE` (TV εκτός σύνδεσης ή η εντολή δεν παραδόθηκε) · `APP_TOO_OLD` (η πολιτική αποθηκεύτηκε, ο ήχος όχι) · `SUPERSEDED` (μια νεότερη εντολή/επαναφορά για το δωμάτιο την αντικατέστησε). Το «UNSUPPORTED» αφορά το εργοστασιακό κλείδωμα μενού.

**Offline TV:** η πολιτική μένει αποθηκευμένη και η TV την παίρνει σε κάθε έλεγχο όταν συνδεθεί. Οι εντολές ήχου μιας επαναφοράς περιμένουν έως **30′** και μετά γίνονται `OFFLINE`, χωρίς επαναλήψεις και χωρίς βρόχους. Η ένταση εκκίνησης εφαρμόζεται έτσι κι αλλιώς στο επόμενο άναμμα.

## 4. API (επέκταση του `POST /api/pms/tv/sound`)

```json
{"action":"reset_policy","roomIds":[2],"preset":"hotel_default|no_max_enforcement|hotel_mode","idempotencyKey":"<uuid>"}
{"action":"restore_sound","roomIds":[2],"idempotencyKey":"<uuid>"}
{"action":"reset_status","requestId":1}
{"action":"preset","preset":{"defaultVolume":8,"maxVolume":30,"enforceMax":true}}
```
Απάντηση: `{requestId, repeated, action, results:[{roomId, roomCode, policySaved, commandIds, status}]}`. Το HTTP 200 σημαίνει «δεκτό και αποθηκευμένο», όχι «εκτελέστηκε».

Εφαρμογή **1.10** (versionCode 11): κάθε έλεγχος στέλνει `prev=<rev πολιτικής που κρατά>` (→ `tv_screens.policy_rev_applied`). Με εφαρμογή 1.9 οι αλλαγές πολιτικής δείχνουν `UNVERIFIED`.

Ουρά: τα βήματα μιας επαναφοράς μπαίνουν μαζί και παραδίδονται με σειρά (UNMUTE, μετά SET_VOLUME, ένα ανά έλεγχο ~20″). Μια νέα χειροκίνητη εντολή εξακολουθεί να αντικαθιστά τις εντολές που περιμένουν.

## 5. Δοκιμές

**Περιβάλλον ανάπτυξης (PostgreSQL + Next.js), επιτυχείς:**
- unit: σχέδια επαναφοράς, κατάσταση ανά δωμάτιο (EXECUTED μόνο με αναφορά, OFFLINE, SUPERSEDED, APP_TOO_OLD, UNVERIFIED χωρίς 1.10)
- προεπιλογές 8/30 ✓ · hotel_default σε 2 δωμάτια: το ένα PENDING, το άλλο APP_TOO_OLD με αποθηκευμένη πολιτική ✓ · ίδιο key → `repeated:true`, καμία δεύτερη εφαρμογή ✓
- restore_sound → UNMUTE και SET_VOLUME 8 (cap 30), παράδοση με σειρά, αναφορές → EXECUTED ✓ · `prev` → policy_rev_applied ✓
- η προηγούμενη επαναφορά που αντικαταστάθηκε → SUPERSEDED (όχι ψευδές EXECUTED) ✓
- no_max_enforcement → enforce=0 (8/30 κρατήθηκαν), PENDING μέχρι το ack της TV ✓ · token και power_method αμετάβλητα ✓
- typecheck, lint, όλα τα tests, build APK 1.10

**HORIZON 112 (εκκρεμούν):** τα 12 σημεία της §6 της προδιαγραφής. Ήδη επιβεβαιωμένο στη v159 (στιγμιότυπο 15/11): ένταση 15% με όριο 30% → EXECUTED 15%· επαναφορά στο μέγιστο· ανάγνωση `hotel_max_volume=100`, `hotel_power_volume=20`, `hotel_menu_key_lock=0`, `hotel_mode` μη αναγνώσιμο.
